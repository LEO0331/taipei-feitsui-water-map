# 臺北市河川水質監測與長期趨勢證據查核決策支援（Policy #13）

本模組回答：**在有限的監測資料查核量能下，哪些測站、月份與指標需要進一步查核資料品質或可比性？哪些觀測足以支持有界線的描述？**

方法版本為 `river-water-longitudinal-evidence-review-v1`，固定分析日為 **2026-10-27（Asia/Taipei）**。這是文件與資料治理查核概念驗證。公布列、實際量測、可比配對、RPI 與官方監管判定採不同准入條件。沒有足夠證據時，系統明確顯示不可用，不補出數字或結論。

## 統計單位與測站身分

九條河川、16 個來源站名、站月機會、CSV 列、含量測列、指標儲存格、跨年配對與 RPI 是不同單位。CSV 只有年、月，不捏造採樣日。資料列 ID 含來源年版、原始檔 SHA-256、CSV 列號、年月與原始河川／站名，不只依賴序號。

目前官方站名可直接對上的有 **15 個**；來源 `青礜溪` 與目前官方 `菁礐溪` 字形不同，保留為 **1 個未配對站名**，不自動認定別名。對全部 16 個來源身分，歷史實體位置不變、設備不變及檢測方法一致的證據仍未准入。現行站名相同不等於已證明四年間為同一實體採樣點；也不推測遷站、增設或停測。詳見[測站身分查核](river-water-policy-station-identity.md)。

## 指標、單位與偵測極限

27 指標共 **20,736 個公布儲存格**：精確量測 **10,684**、偵測極限設限 **1,571**、未檢測 **7,185**、空白 **1,296**、不可解析 **0**、無效精確數值 **0**。逐指標分布與單位見[觀測覆蓋查核](river-water-policy-observation-coverage.md)。

`ND<0.02` 或 `<10` 保留為低於偵測極限，不是 0；`---` 為未檢測，空白為缺值，不認識的文字維持不可解析。`6.50E+03` 保留正確數值意義。每格保存原文、單位、限定詞、可解析數值與偵測極限，並經由外層資料列連回來源雜湊與觀測月份。濃度負數與超出 0–14 的 pH 不准入精確比較。

氨氮有 260 格設限，因此只有 460 列具完整精確四項潛在輸入；此數字不等於 460 個可公布 RPI。銀、汞等指標沒有精確值時，系統顯示無精確配對，不以偵測極限本身或半極限代替。未建立設限資料統計方法，本模組不把精確與設限數值混算一般平均，不製造趨勢方向或顯著性。

## RPI 官方方法與准入

環境部[官方定義](https://wq.moenv.gov.tw/EWQP/zh/Encyclopedia/NounDefinition/Pedia_37.aspx)以 DO、BOD5、SS、NH3-N 的濃度（mg/L）分別轉為 1／3／6／10 點，再將四項點數平均。官方文字表有 DO 4.5–4.6、BOD5 4.9–5.0、SS 49.9–50.0、NH3-N 0.99–1.00 之間的顯示精度空隙，並提及檢測報告位數規定；本次未取得足以確認任意小數輸入處理與 RPI 四捨五入的適用完整規範。

實作保留官方明確範圍的單項點數函式與邊界測試，但 **Research-reproduced RPI（研究重現 RPI）目前不可用：合格 0，排除公布列 768**。另一獨立限制是站月同列尚不足以獨立證明四格為同次實體採樣，也未比對到官方公布 RPI。缺任一項、設限、空白、未解析、單位不合或未來列均不能被拼接成 RPI。

這項不可用狀態不是官方方法錯誤或監測缺陷的結論，而是本研究尚未完成所需方法與採樣脈絡查核。啟用前須保留適用位數／捨入規範、同次採樣或官方月份組合規則，以及可獨立核對的官方範例。完整逐項表與阻礙見[RPI 方法](river-water-policy-rpi-methodology.md)。水庫 CTSI 不與河川 RPI 混合。

## Mode A／B／C

**Mode A：監測證據整備查核。** 單位為站名身分 × 來源月份。768 個公布候選中，736 個可進行目前文件查核，32 個未來預留列明確排除。Tier A＝46、Tier B＝690、Tier C＝0。A 為來源／身分問題，B 為完整度／可比性問題，C 為例行文件查核。A 的 46 個候選都來自未配對站名的截至當月月份；當月空白另有待發布狀態，不稱為歷史逾期。分級表示查核順序，不表示污染嚴重度。

**Mode B：可比配對與 RPI 證據。** 候選單位為站身分 × 指標 × 相鄰跨年視窗（2023–2024、2024–2025、2025–2026）。嚴格模式要求歷史實體身分與方法證據，故目前 **0 個合格**。另有明示限制的「同來源站名精確配對描述」：1,296 個待查視窗中 **823 個有限視窗**、**7,239 個同月份指標配對**，其餘 473 個不合格。配對可能跨指標重用相同站月列，不是獨立採樣次數。每個視窗顯示配對數與 12 個月中的排除數，不把完整年與不完整年當成等覆蓋。有限模式不升格為已驗證長期趨勢，不產生趨勢方向、統計顯著性或因果效應。

**Mode C：因果／監管判定。** 不可用。月資料不能單獨回答污染來源、工廠責任、政策介入效果、排放許可違規、游泳或飲用適宜性。需依問題補足採樣／實驗方法、適用水體標準、雨量流量與季節脈絡、排放來源、管轄與許可、官方符合性判定及必要現地驗證。

## 敏感度與實際 ID

預設 5 名額兩策略共享 5 個 ID、增加 0、移除 0，合格母體與河川／站數變動均為 0。全部名額兩策略的集合相同，均為 736 個候選。

將年份範圍縮為 2026，合格數由 736 變為 **160**（A10、B150），排除 32 個未來預留列，母體差 **−576**。5 名額改為 `A:station-b304f8239c8754ee:2026-01` 至 `2026-05`，相對全年度共享 0、增加 5、移除 5，河川／站數不變。這是資料範圍變動，不能解釋為同母體策略優劣或水質變化。嚴格／有限 Mode B 的 0→823 也是證據規則改變，不是環境改善。

## GIS 證據與介面

本政策准入座標與地圖圖釘為 **0**。目前網頁顯示的個別位置資訊不代表已核對全部來源站名、座標參考系與歷史年版；未達 `coordinateStatus: verified` 與來源證據條件時，採河川／站表與量測圖，不以河名中心點、相近橋梁或推測位置補點。不能由位置接近推論上下游污染傳遞或因果。原河川探索模組的座標契約保留。詳見[地理證據查核](river-water-policy-geographic-evidence.md)。

介面整合於既有「河川與生態」導覽，獨立 lazy panel 可由 `#river-policy` 開啟，支援繁中／英文與既有語言切換。來源、年份、河川、測站、指標與證據要求可篩選；圖只呈現有效精確月值，未知月份不補 0、不連線跨過缺口。來源版本、指標限定詞、覆蓋矩陣、RPI 阻礙、候選說明、名額、策略重疊及敏感度均可查閱。

## 重現性、匯出與驗證

資料管線為「獨立官方來源留存 → 離線來源稽核 → 純函式分類／配對／查核 → 內容定址不可變快照 → 最後原子更新 current pointer → 瀏覽器核對位元組 SHA-256」。相同准入原始檔與配置產生相同分析位元組；失敗下載、格式改變或重建驗證失敗不能覆蓋上次已接受來源與快照。快照 ID／完整雜湊請以[交付報告](river-water-policy-delivery.md)與目前指標檔為準。

`npm run data:fetch:river-water-policy` 預設離線；只有明確 `--refresh` 取得網路新版本，接受版本需另有明確准入動作。一般重建與驗證使用 `data:audit:river-water-policy`、`data:build:river-water-policy` 與 `data:verify:river-water-policy`，不執行廣泛的 `fetch:data`，不刷新水庫、生態或其他模組。

匯出名稱為「河川水質監測證據查核摘要／River Monitoring Evidence Review Briefing」。JSON 與 CSV 包含政策／方法、固定分析日、快照 ID／雜湊、來源年版、篩選配置、名額策略、已選候選、Tier／問題代碼、限定詞、配對有效性、RPI 准入、排除與限制。CSV 處理引號及公式注入前綴，結果順序固定，空結果有效，檔案大小有上限，不輸出內部路徑、密鑰或官方法遵報告標籤。

基線於最新 main `94b460758bda198bd1b83a0e7839814a944898ec` 執行：`npm ci`、完整離線轉換、65 個既有測試與 TypeScript、一般及 Pages 建置通過；Windows `bash ./init.sh` 因 `Bash/E_ACCESSDENIED` 無法啟動，已執行等效命令。最終測試數、精確快照重建、瀏覽器五個視窗尺寸、鍵盤／匯出／失敗重試、console／請求查核與實測效能，統一記錄於[交付證據](river-water-policy-delivery.md)，不以預期結果冒充已跑結果。

本政策保留既有水庫、河川探索、生態、自來水與防汛整備模組。沒有新增後端、資料庫、登入或正式瀏覽器政府 API 相依。後續需補的是歷史測站定位／方法、適用 RPI 精度規範與同次採樣身分等官方證據；不能靠調整門檻創造結果。Policy #13 為本次唯一政策範圍，不啟動 Policy #14，PR 不自動合併。
